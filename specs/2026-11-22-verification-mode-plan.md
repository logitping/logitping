# Verification mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every probe given a claimed model reports a claim verdict, and, with the bundled default bank, the claim's measured acceptance rates; `--claim` sets the CLI exit code from the verdict.

**Architecture:** `src/core/claim.ts` matches a claim to a bank model, computes the verdict from the result's `candidates`, and derives rates (Wilson ranges, `outside`, `mostAccepted`) from raw counts. `src/data/claim_rates.ts` validates and serves the generated `src/data/claim_rates.json`, which `npm run bank:evaluate` writes from the same scoring pass as the evaluation report. The engine attaches `claim` to results; the CLI prints it and maps it to exit codes under `--claim`.

**Tech Stack:** TypeScript ESM, Node ≥ 22, vitest, commander.

**Spec:** `specs/2026-11-22-verification-mode-design.md`

## Global Constraints

- Node ≥ 22, TypeScript ESM, no new dependencies.
- `src/core`, `src/math` and `src/probes` import no `node:` modules.
- `claim_rates.json` is generated by `npm run bank:evaluate`, which needs the git-ignored maintainer corpora; CI and users only read the committed file.
- No local paths, usernames or scratchpad paths in generated files, docs or commits.
- Run tools as `./node_modules/.bin/vitest run`, `./node_modules/.bin/tsc --noEmit`, `npm run build`, `node scripts/...` (npm is a Socket wrapper).
- Never call a verdict "verified"; never present a rate as the probability that the endpoint serves the claimed model; never describe models whose runs pass as a claim as related, derived or trained from one another.
- Rates only for probes scored with the bundled default bank loaded by the engine itself (no `bank` option), never cross-transport.
- Exit codes: with `--claim`, `0` CONSISTENT, `3` INCONSISTENT, `2` NOT_CHECKED or NOT_ENROLLED; without `--claim`, unchanged (`0` IDENTIFIED, `2` other statuses); errors `1`, interruptions `130`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A claim with a `vendor/` prefix, different letter case, or an empty last segment (`openai/`): matched as collection settings are, never throwing.
2. A short reply or an incompatible default bank (CLI driver) must give NOT_CHECKED, never INCONSISTENT; with `--claim` that exits 2.
3. A caller-supplied bank, even an unmodified `defaultBank()` copy, must never get rates.
4. A malformed `claim_rates.json` must throw `INVALID_BANK`, not a TypeError, and only when a claim needs it.
5. Ordering determinism of rows and `mostAccepted` independent of locale (code-unit comparison).
