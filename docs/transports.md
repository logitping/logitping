# Transport limitations

[Back to README](../README.md) · [CLI reference](cli.md) · [Security policy](../SECURITY.md)

Read these limitations before probing local developer CLIs. They reuse installed executables, authentication, and parts of the user environment. Only run them with backends and binaries you trust.

- The HTTP adapter handles OpenAI-compatible Chat Completions, OpenAI Responses, and Anthropic Messages SSE. As the SSE specification requires, it ignores unknown event fields. It ignores reasoning text, tool output, usage counters, and model-name metadata. Chat Completions requests default to `max_tokens`; use `--token-limit-field max_completion_tokens` (library: `tokenLimitField`) for OpenAI models requiring that field, or `--api-format responses` (library: `apiFormat`) for `max_output_tokens`. The budget may include reasoning, so raise it with `--max-tokens` (library: `maxTokens`) to leave room for the requested visible integers.
- Claude runs in print mode with `stream-json`, verbose events, and partial messages. Duplicate final text is ignored. Tools, hooks, slash commands, and MCP configuration are disabled for this invocation; if a CLI version ignores those flags, any tool request or result still aborts the probe. Local login is reused without reading or copying credentials. See the [official Claude streaming interface](https://code.claude.com/docs/en/headless#stream-responses).
- Codex runs `exec --json` in an ephemeral read-only session, in an empty temporary directory, with approvals disabled. Configuration overrides (`-c features.<name>=false`) turn off Codex features that let a backend act on this machine, including the shell tool, image viewing, browser and computer use, apps and plugins, sub-agents, and user hooks; a Codex version without one of these features ignores its override. Before each probe, the driver runs `codex mcp list --json` with the probe's environment, directory, and overrides, then disables every enabled MCP server for that run with `-c mcp_servers.<name>.enabled=false`. Codex merges `-c` tables into your configuration, so an empty `mcp_servers` override would remove nothing. The probe refuses to start if Codex cannot list its servers as JSON, or if a server name has characters other than letters, digits, `-`, and `_`, because a dotted override cannot address it. The overrides narrow the tool set but do not guarantee it is empty: codex-cli 0.160.0 keeps `unified_exec` enabled despite its override. Only completed `agent_message` events are sampled. Any other item except reasoning (a command, file change, MCP call, or web search) aborts the probe and terminates Codex as soon as the item starts. For any tool that remains, termination races the action: it limits, but cannot prevent, a backend running that tool on this machine. Probe Codex only through backends you would trust with that access; every Codex result repeats this warning. Installed user configuration and authentication remain in effect. The overrides also change the context Codex sends with the probe, so re-enroll Codex banks collected with earlier versions of this driver. The [documented Codex event format](https://learn.chatgpt.com/docs/non-interactive-mode#make-output-machine-readable) does not guarantee token deltas; this adapter reports message granularity and disables early-stopping savings claims.
- Subprocesses receive the prompt on stdin using argument arrays, never a shell command line. On Windows, an npm-installed CLI is a `.cmd` shim that `cmd.exe` runs, so a `--model` override may contain only letters, digits, and `. _ : / @ [ ] -`. A CLI inherits your environment except `LOGITPING_API_KEY`, which only API probes use. Breaking consumption, aborting, or interrupting `lping` sends SIGTERM, escalating to SIGKILL after one second if necessary. Temporary working directories are removed afterward. CLI behavior and inherited global customization still need validation in each deployment; read-only mode is not a hermetic execution environment.
- The report measures elapsed wall time and skipped **integer sample budget**, not saved provider tokens, billing, or counterfactual latency. A provider may buffer output or continue generation after disconnection. There is no supported basis for a fixed 70% savings claim.
- This is behavioral fingerprinting, not access to logits, proof of weights, or cryptographic provenance. A knowledgeable proxy can detect and imitate probes. Agent routing, fallback models, prompt adaptation, reasoning policies, and temperature changes can alter results.

MCP servers and agent plugins are outside this version's scope.

## Platform coverage

CI runs on Linux with Node.js 22 and 24. The release review also exercised the test suite and tarball on macOS with Node.js 26.10. Windows is not covered by CI; the Windows argument restrictions above do not establish complete Windows compatibility. Claude and Codex versions and global configuration can change transport behavior, so validate the versions used in your deployment.
